## 一、 你以为的单兵作战，其实是“隐形团队”

先说个颠覆认知的结论：**你可能已经在用多 Agent 了。**

当你在对话框里敲下“帮我看看这个项目结构”时，背后干活的根本不是“一个 AI”。实际上，WorkBuddy 会自动派一个小助手（子 Agent）去扫描文件、搜索关键词、梳理逻辑，最后把结果汇总给你。

整个过程你是无感的，你只会觉得：“咦，今天回复怎么这么快？内容还这么详细？”

这就是多 Agent 的第一层境界：**自动子 Agent**。系统自己判断什么时候该“摇人”。

星哥给大家总结了几个常见的“隐形小助手”：

- **Explore（探索者）**：擅长快速扫描项目、搜代码。你的感觉是：秒回，直接给文件列表。
- **Plan（规划师）**：能力更强，做复杂分析。你的感觉是：分析结果比平时深刻得多。
- **general-purpose（通用型）**：万金油，啥都能干。你的感觉是：复杂任务被拆成几步并行搞定了。
- **Fork（分身）**：带着你的完整对话记忆去干活。你的感觉是：“另一个我”在帮忙，因为它记得前文。



👀 **星哥教你怎么识破它？** 如果你好奇背后是不是多 Agent 在跑，盯紧右侧的**工具调用面板**。看到 `Explore`、`general-purpose` 等标签，或者发现回复速度奇快、内容分了好几个角度，那就是“隐形团队”在发力了。

## 二、 如何主动召唤“分身”？

被动触发虽然爽，但想榨干 WorkBuddy 的性能，咱们得主动出击。星哥分享两个我压箱底的实战招式。

### 招式一：极简并行法（一句话干两件事）

以前我要准备一篇推文，得先让 AI 查资料，等它写完，再让它排版。一来一回，时间全浪费在等待上了。

后来我换了个话术，在提示词里加了两个字：

> “帮我**同时**做两件事：1）搜一下 2026 年最热门的 3 个 AI 效率工具，列出特色；2）帮我写一个 HTML 页面，做个简单的工具对比表单。”

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1782269557662.png?tx)

奇迹发生了——它真的**同时**干了！两个子 Agent 各干各的，一个搜网页，一个写代码，结果几乎同时拍在我面前。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1782269657798.png?tx)

💡 **星哥划重点**： 触发这个模式的咒语就是 **“同时”** 或者 **“并行”**。 **适用场景**：几个互相不依赖的小任务。比如“同时翻译文档 + 同时清洗数据”，省下来的时间拿去喝杯咖啡不香吗？

### 招式二：虚拟团队法（打造专属 AI 部门）

如果说“并行”是几个临时工一起干活，那“Team 模式”就是给你配了一个正规军。

起因是我要做个深度测评：调研云原生工具、写测评文章、最后做合规审查。这三件事能力模型完全不同。

我试着这样给 WorkBuddy 下指令：

> “帮我创建一个团队，3 个角色：
>
> 1. **调研员**：搜索 2026 年最受欢迎的云原生工具，整理成表格。
> 2. **主笔**：根据调研结果写一篇 1000 字的深度测评草稿。
> 3. **审查员**：检查文章有没有错别字、数据错误和逻辑漏洞。 三个人同时开工，最后汇总给我。”

大家猜怎么着？工具面板里真的出现了三个不同的 Agent 在疯狂输出！最后交出了表格、草稿和审查意见。效率直接翻倍。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1782269863943.png?tx)

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1782270264314.png?tx)

🔥 **这里有个核心细节（敲黑板）：权限隔离。** 在这个团队里，调研员只能搜索，主笔能写文件，审查员**只能读不能改**。各司其职，不会互相把代码改乱。这就是 Team 模式比普通并行高级的地方：**角色定位 + 权限隔离**。

**怎么触发 Team 模式？** 星哥最推荐“说人话”的方式，不用记复杂格式，直接描述分工： *“我需要一个负责调研的、一个负责写代码的、一个负责检查的，帮我搞定这件事。”*

```
我需要做一个外贸独立网站，请帮我创建一个团队
一个负责调研的、一个负责写代码的、一个负责检查的，
帮我搞定这件事。
```



## 三、 避坑指南：什么时候该用多 Agent？

工具虽好，可不要贪杯。多 Agent 不是万能药，用错场景反而降速。星哥总结了一个简单的判断矩阵：

✅ **闭眼用多 Agent 的场景：**

1. **任务无依赖**：A 和 B 谁先干都行，互不影响。
2. **能力跨度大**：一个需要联网搜索，一个需要本地写代码。
3. **工作量大**：并行处理能带来肉眼可见的提速。

❌ **千万别硬拆的场景：**

1. **强依赖关系**：B 必须等 A 的结果才能开始（比如：先查资料，再根据资料写方案）。
2. **简单任务**：简单的问答或改个 Bug，单 Agent 响应更快，别杀鸡用牛刀。
