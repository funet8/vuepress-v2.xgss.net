# Hermes‑Agent 对接钉钉（Docker 部署版）

> Hermes 钉钉使用 **Stream 模式（WebSocket 长连接）**，**不需要公网 IP / 回调 URL**，内网服务器即可跑。 
>
> 交互规则：私聊直接发消息；群聊必须 @机器人 才响应。

## 二、Docker 环境变量配置

### 有三种方法添加（星哥用的第二种）

### 1.Hermes 钉钉靠环境变量注入

`.env` 路径容器内是 `/opt/data/.hermes/.env`，

宿主机对应： `/home/data/docker/hermes/data/.hermes/.env`

追加配置：

```
# 钉钉必填
DINGTALK_CLIENT_ID=你的ClientID
DINGTALK_CLIENT_SECRET=你的ClientSecret

# 可选：钉钉用户ID白名单，逗号分隔；不填则企业内全部可访问
# DINGTALK_ALLOWED_USERS=dingxxxx,dingyyyy
```



### 2.进入到Hermes后台添加

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1787888705723.png?tx)

查看是否添加到变量文件中。

```
[root@test-node110 hermes]# cat /data/docker/hermes/data/.env |grep DINGTALK
DINGTALK_CLIENT_ID=*****
DINGTALK_CLIENT_SECRET=****
```

有信息说明添加成功

重启docker

```
# 重启hermes

cd /home/data/docker/hermes

docker compose restart hermes
```

### 3.命令行导入

Hermes 的钉钉机器人由 **gateway 服务** 负责，不是主 hermes 服务，容器启动后进入容器执行：

```
# 进入容器
docker exec -it hermes bash

# 交互式配置向导（也可以不用，上面.env写好就跳过）
hermes gateway setup

# 启动网关
hermes gateway run
```

查看网关状态

```
hermes gateway status
```

日志看到 `DingTalk connected via stream` 代表钉钉长连接成功。



启动：`docker compose up -d` 进入容器开启网关：

```
docker exec -it hermes-agent bash
hermes gateway run
```

> 💡 注意：docker 镜像默认不会自动启动 gateway，需要手动执行 `hermes gateway run`；
>
> 想开机自启 gateway 需要自定义 s6 服务或者写 supervisor。

## 常见坑

1. **No session_webhook available**

> 网关重启后旧会话失效，重新发一条消息即可，钉钉 Stream 模式限制，非 bugGitHub。

1. 配置完不生效：

- 确认钉钉应用发布、消息模式是 **Stream 模式**，不是 HTTP 回调；
- 确认环境变量已经正确加载 `hermes doctor` 可以看到读到的配置；
- 重启 gateway：`hermes gateway restart`

1. Docker 中缺失钉钉依赖包报错

```
#容器内执行
pip install dingtalk-stream httpx alibabacloud‑dingtalk
```

hermes-age...

1. 群聊 @机器人没反应：

- 确认机器人已经加入该群；
- 检查 `DINGTALK_ALLOWED_USERS` 白名单是否限制用户；
- 看 gateway 日志有没有收到钉钉事件。
