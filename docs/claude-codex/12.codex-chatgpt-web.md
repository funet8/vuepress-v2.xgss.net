# ChatGPT的用不完的WEB额度，终于能喂给 Codex 了

**导读：** 你花的 20 刀，买回来的是两个互不相通的额度池——聊天那个月月剩一大截，写代码那个月月透支。这篇讲清楚社区怎么把这堵墙拆开、两套方案分别适合谁。



我太懂这种憋屈了。

月底打开 ChatGPT 网页版，额度还剩一大截，绿油油地躺在那儿；一进 Codex，想让它帮忙改两段代码，红色提示弹出来——本周额度见底。

同一笔钱买的东西，凭啥两个地方各记各的账？

这事儿在我心里憋了很久。直到前两天，有人把它摆到了台面上。



## 两个额度池

ChatGPT 的付费订阅，背后是**两个额度池(web和codex)**。

一个在网页版里，管聊天。

Plus 每月 20 美元，你我这种普通用量的，到月底基本花不完。

另一个在 Codex 里，管干活。

Codex 是 OpenAI 家的编程助手，你把任务丢给它，它自己读代码、改代码、跑测试。可它跑几个重任务，额度就烧光了。

一个用不完，一个不够用。**两本账，互不相通。**

官方没解释过为什么要分开算。可从计量方式看，聊天是聊天，干活是干活，分得清清楚楚——怎么算都不像巧合。

对咱们来说，网页版里那用不掉的一半，每个月都在白白流走。

## GPT-6上线之后Token炸了！

GPT-6 Astra 九月初上线，老问题一下被放大。

模型越能干，你敢丢给它的重任务就越多，Codex 的额度烧得越快。Plus 用户一个月的干活额度，撑不过两三个正经项目。

另一边呢？网页版拿着更强的模型、更长的上下文，额度月月睡大觉。

对天天跑重任务的人来说，这就是**泼天的富贵搁那儿没人动**。

**这儿得插一句我核实过的事**：不少说法讲 Codex 是"按次数"扣额度的，其实不准。Codex 扣的是**推理时长**——单位是一个 5 小时滚动窗口里，你能用掉多少"思考时间"。

有社区实测，早期 Plus 配 GPT-5.4 的时候，模型思考 1 分钟，就吃掉这个窗口的 2.5% 左右。想明白这点你就不奇怪了：为什么有的任务点一下就没，有的一整天都跑得动。它烧的不是次数，是脑子转的秒数。



## 网页版没长手

想让闲置的聊天额度去干活，先得过一关。

网页版 ChatGPT，代码贴进对话框它看得懂；可你电脑上那个项目，它碰不到。它没有手。

转机是 OpenAI 自己递过来的——ChatGPT 桌面版开了**开发者模式**，开放了 `MCP` 连接器。

MCP 你可以理解成给 AI 预留的**插座**。网页里的 ChatGPT 插上这个插座，就能摸到本地工具。放在两年前，这事想都不敢想：网页版对本地世界是绝缘的，标准一通，墙角下就裂了条缝。

插座有了，剩下就是谁来接水管。

顺带提一句，这条路子你要是自己搭，会踩到个小坑：ChatGPT 网页版**够不到你电脑的 localhost**，必须走官方安全隧道，或者自建一条 HTTPS 反向代理。官方路径是「设置 → 安全与登录 → 打开开发者模式」，再去 `chatgpt.com/plugins` 点加号，填一个以 `/mcp` 结尾的 HTTPS 地址，认证方式保持默认的 OAuth——改成 None 就变成"能列出工具、但一个也跑不了"。



开源社区几天之内给了两个答案，路子差得很远。

## 方案一：安装 codex-chatgpt-web

https://github.com/miuuyy/codex-chatgpt-web

项目叫 `codex-chatgpt-web`，独立开发者 miuuyy 写的。

做法很直接——把 ChatGPT 网页版**装进 Codex 的模型选择器**。

装完你在 Codex 里选模型，列表里会多出一串名字带 `(Web)` 的：`GPT-5.6 Sol (Web)`、`GPT-6 Pro (Web)`……免费账号给一档，Plus 给到高推理档，Pro 连顶配都给。

任务照旧在 Codex 里发，但真正动脑子的，换成了你那个总也用不完的网页版 ChatGPT。

代价也有：Plus 一次能装进脑子的代码量有限。好在压缩机制复用了 Codex 原生的，超长任务也能接着跑，作者还留了个实验性的三倍扩容开关。

实测 Plus 跑中高档，大概有 9 万 token 的窗口，开三倍能顶到 27 万左右。

它连安装都替你打包好了，浏览器和运行时一起塞进启动器，Chrome、Node 都不用自己装。

## 方案二：codex-with-chatgpt

另一个项目叫 `codex-with-chatgpt`，作者自己给它起了个简称：**C2C**。

https://github.com/XiaoDuoYa/codex-with-chatgpt

它的主张一句话就能说完——**ChatGPT 想，Codex 干**。

你告诉 Codex 要做什么，它先去问网页版 ChatGPT 要一份实施规划，然后自己照着改代码、跑测试。改完还不算完，得把真实的改动和测试记录交回给 ChatGPT 复查一遍，才算交工。

这个项目里有条规矩我特别喜欢，作者写在协议文档里：

> 不要因为 Codex 说自己做成了，就假定它真做成了。

所以 ChatGPT 复查的时候，看的不是 Codex 的自述，而是真实的 git diff 和测试输出。这一点，比很多"自己给自己判卷子"的 agent 都实在。





## 星哥的总结

我自己是这么分场景的，可以直接抄作业：

- **只想让 AI 帮我审代码、出方案，不敢让它碰仓库** → 用 `codex-with-chatgpt`（C2C）。9 个只读工具，心里最踏实，装起来也最省事。
- **想长期让 ChatGPT 直接改本地项目** → 用 `codex-chatgpt-web`。体验最顺，浏览器和运行时都打包好了。
- **仓库里有公司代码、有密钥** → 上面两个都先别碰；真要用，至少把敏感目录隔出去再试。

还有个更省心的思路：你要真把 AI 编程当生产力，与其在订阅额度里抠来抠去，不如搞台常驻的云服务器，把开源的 coding agent 架上去，按量计费，用多少花多少，不用天天跟额度窗口较劲。
