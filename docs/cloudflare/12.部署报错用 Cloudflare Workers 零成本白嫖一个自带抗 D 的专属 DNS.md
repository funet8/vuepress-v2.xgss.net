星哥我就在想，既然 Web 服务都能 Serverless 化，那 DNS 为什么不行？



## 主角登场：跑在边缘计算的 DNS

最近星哥在 GitHub 上发现一个极其对胃口的开源项目：**Serverless-DNS**。

简单粗暴地说，它就是一个用 JS/TS 写的 DNS 服务端。但它**不需要你买 Linux 主机**，而是原生设计用来跑在 Cloudflare Workers、Deno Deploy 这类 Serverless 边缘计算平台上的。

它接收基于 HTTPS 的 DNS 请求（也就是 DoH），在边缘节点进行解析和规则匹配，然后把结果返回给客户端。

## 三个核心爽点

为什么说这个项目能戳中痛点？星哥给大家总结了三个核心爽点：

### **1. 降维打击的稳定性，自带顶级抗 D**

把 DNS 放在 Cloudflare 上跑，最大的优势就是稳。你的解析服务瞬间拥有了 CF 遍布全球的边缘节点，响应延迟极低。

最关键的是，**你根本不需要担心被 DDoS 打瘫**。CF 庞大的基础设施，就是你这套服务的“免费高防壳”。

### **2. 真正的零运维，极度舒服的“白嫖”体验**

没有 Linux 系统需要你打安全补丁，没有 Docker 容器会因为内存泄漏 OOM 重启。

部署完代码，它就老老实实待在那处理请求。配合 CF Workers **每天 10 万次的免费请求额度**，个人、家庭甚至小型团队自用，这辈子都很难把免费额度跑完。真·白嫖！

### **3. 用写代码的方式管理解析规则**

传统的 DNS 区域文件改起来死板又枯燥。但在 Serverless-DNS 里，**一切都是代码**。

你可以非常灵活地写几行 JS 逻辑：
- 根据请求 IP 地区返回不同结果，实现智能分流；
- 结合 CF 的 D1 数据库，搞一个超低延迟的动态 DDNS；
- 写个正则，把各种追踪器和广告域名的请求直接在云端掐断。

## 本地部署

得益于前端生态的成熟，部署这类项目就是几行命令的事儿。如果你本地有 Node.js 环境和 CF 命令行工具 `wrangler`，整个过程不超过两分钟：

```bash
# 1. 克隆代码到本地
git clone https://github.com/serverless-dns/serverless-dns.git
cd serverless-dns

# 2. 安装依赖包
npm install

# 3. 自定义规则（按需修改 src 下的配置文件）

# 4. 一键起飞，推送到你的 Cloudflare Worker 节点
npx wrangler deploy
```
