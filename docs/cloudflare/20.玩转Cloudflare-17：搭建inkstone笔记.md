## inkstone简介

inkstone，一个跑在 Cloudflare Workers 上的自托管网页笔记。

仓库 7 月 30 号才建，到现在三个月，**1144 个 Star，1039 个 Fork。**

正常开源项目，Fork 数一般是 Star 的十分之一。它俩几乎 1:1。

为什么？因为**它的部署流程第一步就是 Fork。** 

你得把它复刻到自己的 GitHub 仓库，再让 Cloudflare 从你的仓库拉代码构建。

也就是说，这一千多个 Fork 里，很大一部分是真动手部署了的人。不是"收藏一下改天再看"，是"我已经跑起来了"。

这个比例，比 Star 数诚实得多。

## inkstone优点

我其实不太需要 Obsidian 那套插件生态——两百多个插件，我常年用的就三个。我要的是：**能写、能找、能同步、能带走。**

它给的比这个多。

**写。** 编辑器是 CodeMirror 6，可以把两篇笔记拆成左右两组并排写——一边查资料一边记，不用来回切窗口。还有专注模式、打字机模式、大纲导航、自动保存，每次改动都留版本历史。

**语法。** Obsidian 那套基本都认：WikiLinks、块引用、笔记嵌入、Callout 提示块、折叠块、标签页、数学公式、Mermaid 图表、Front Matter。你以前的 Markdown 搬过来不用改。

**找。** 全文搜索走 D1 的 FTS5 索引，官方说对中文做了分词优化。另外可以开一层基于 Workers AI 的语义搜索——搜"上次那个关于备份的想法"，也能翻出来。

**离线。** 能装成 PWA，断网照样打开。离线期间的改动会进一个待写队列，联网自动补交。它还做了乐观并发和冲突副本，两台设备同时改一篇不会直接互相覆盖。

**带走。** JSON 和 ZIP 两种导出，附件能单独导，还能配 WebDAV 或 S3 定时异地备份。

最后这条是我最看重的。**一个笔记工具敢不敢让你随时打包走人，基本能看出它的底气。**



##  inkstone的MCP

这部分是我觉得它跟同类产品拉开差距的地方，值得单独讲。

它内置了一个远程 MCP 服务。授权走 OAuth 2.1（PKCE），你也可以给账号签一个 `ink_` 开头的 API Key，随时能撤销。

这意味着什么？

**你手机里、电脑里那个 AI 助手，可以直接检索和读写你的笔记库。**

不是"复制一段笔记粘贴给 AI"，是 AI 自己去你库里搜。你问"我上个月记的那个 Nginx 配置怎么写的"，它去翻，翻到了直接给你。

而且它的权限切得挺细：读取有范围限制、写入带版本校验（防止 AI 把你刚改的内容盖掉）、回收站是单独一个权限、每个账号的授权可以单独管。

我见过太多"AI + 笔记"的方案，最后都停在"把内容复制出来喂给模型"这一步。

**能原生接进去的，是另一个量级的体验。**



## 动手安装inkstone

我把官方流程捋一遍，你照着点就行。

### **第一步，Fork。**

 打开 `github.com/shuaiplus/inkstone`，右上角 Fork 到你自己的仓库。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1793240092168.png?tx)

### **第二步，Cloudflare 里连仓库。** 

登录 Cloudflare，左侧「计算 → Workers 和 Pages」→ 创建应用程序 → 继续使用 GitHub → 授权后选中你刚 Fork 的 inkstone。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1793240291432.png?tx)

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1793240315787.png?tx)

构建命令和部署命令按你选的存储模式填：

使用 R2 时，

构建命令填 npm run build

部署命令填 npm run deploy

如果你打算用 KV 模式，把部署命令改成 npm run deploy:kv

```bash
npm run build      # 构建，两种模式都一样
npm run deploy     # R2 模式
npm run deploy:kv  # KV 模式
```

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1793240417620.png?tx)

等它跑完，页面出现 Success 就成了。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1793240566239.png?tx)



### **第三步，绑自己的域名。** 

这一步别省，原因下面讲。

部署完 Cloudflare 会送你一个 `xxx.workers.dev` 的域名。这个后缀在国内的连通性一直不怎么样，很多人是打不开的。

点「添加域名」，选你自己已经托管在 Cloudflare 的域名，前缀随便起（比如 `ink`），加完就能用自己的地址访问了。

关于 KV 和 R2 怎么选，官方文档写得很直白：

- **笔记正文永远存在 D1 里**，跟你选哪个无关
- **KV 和 R2 只决定附件和头像这类二进制文件放哪**
- R2 要绑信用卡才能开通；KV 不用绑卡，但单个文件有体积限制

所以上手阶段直接 KV，等附件攒多了再迁 R2，完全来得及。

## 数据在哪里

自托管最该问的就是这句。

它把存储拆成了这几块：

| 组件                   | 存什么                                                       |
| ---------------------- | ------------------------------------------------------------ |
| Cloudflare D1          | 账号、笔记、文件夹、标签、设置、版本历史、分享记录、全文索引 |
| R2 或 Workers KV       | 附件、上传的头像                                             |
| Workers KV（OAUTH_KV） | OAuth 授权码和 Token，**不存笔记正文**                       |
| Workers AI             | 可选的语义搜索向量                                           |
| 浏览器 IndexedDB       | 本地缓存、离线待写队列                                       |
| WebDAV / S3            | 你自己配的异地备份                                           |

翻译成人话：**数据库在你账号里，附件在你账号里，运行环境也在你账号里。** 作者看不到你的内容，因为他压根没有你的实例。

这跟"某个团队在海外机房替你保管"是两件事。前者是租房子，后者是借住。



## Cloudflare免费额度

这部分我特意去核了官方定价页，2026 年 10 月的口径。

Cloudflare 免费档给它提供的底座，额度是这些：

| 资源       | 免费额度                                          | 用它干嘛           |
| ---------- | ------------------------------------------------- | ------------------ |
| Workers    | 10 万次请求/天                                    | 整个应用跑在这上面 |
| D1         | 读 500 万行/天、写 10 万行/天、5GB 存储           | 笔记正文 + 索引    |
| KV         | 读 10 万次/天、写 1000 次/天、1GB                 | 附件（KV 模式）    |
| R2         | 10GB 存储、100 万写 / 1000 万读每月、出口流量免费 | 附件（R2 模式）    |
| Workers AI | 1 万 Neurons/天                                   | 语义搜索向量化     |

数字看着抽象，换成具体量你就知道松紧：

**D1 那 5GB。** 两千字的中文笔记，存成 Markdown 大约 6KB。5GB 能装**八十多万篇**。就算版本历史再叠两三倍，你写一辈子也碰不到顶。

**D1 那 10 万行写入。** 每保存一次笔记算一行，加版本历史可能两三行。也就是说一天存几万次都够。个人用户根本摸不到这条线。

**KV 那 1000 次写。** 这个数字看着紧，但别忘了正文在 D1。KV 只管附件——**一天传一千张图才会爆**。真正会踩到这个限制的，是拿 KV 当缓存或计数器用的玩法，不是笔记。

**Workers AI 那 1 万 Neurons。** 官方口径，1 万 Neurons 大约等于 1500 到 15000 次向量化，看模型大小。也就是说一天给一两千篇笔记建索引，是够的。

结论很清楚：**自己用，这套额度是用不完的。** 但如果是三五个人拿它当团队 wiki，版本历史、全文索引、附件会一起往上叠，那就得盯着 D1 的写入量了。

顺便说一句，既然能配 WebDAV/S3 异地备份，我建议真配一个。备份这事最怕"只有一个副本还放在别人家"——**笔记这套东西，异地一份是底线。**



## 需要注意的点

夸完了，说点不好听的。这三点我建议你在点 Fork 之前先想清楚。

### **第一，域名必须绑，别偷懒。**

`workers.dev` 在国内的连通性常年不稳，你自己电脑上能开，手机 4G 上可能就转圈。这跟你笔记写得好不好没关系，纯粹是网络路径的问题。花两分钟绑个自己的域名，能省掉以后无数次"怎么打不开"。

### **第二，项目才三个月。**

7 月底建仓，两个多月发了 7 个版本，最新 v0.8.0。这个迭代速度很猛，但也说明：**它还在长身体。**

作者是一个人。数据库升级靠带版本号的迁移脚本自动跑，官方自己也提醒——升级前先导出一份完整备份。

这句话你得当真。**自托管应用的备份，不是"有空再做"，是"升级之前必须做"。**

### **第三，LGPL-3.0 不是"随便用"。**

自己部署自己用，没任何问题。但如果你打算改一改再对外分发，那得按协议来。开源不等于没规矩。



## 跟 Obsidian、Notion 怎么选

我不觉得它能替掉 Obsidian。

插件生态、本地文件、社区主题，这三样短期内没人能打。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1793240064049.png?tx)

它擅长的是另一个位置：

|            | inkstone            | Obsidian     | Notion               |
| ---------- | ------------------- | ------------ | -------------------- |
| 数据在哪   | 你自己的 Cloudflare | 你自己的硬盘 | 它的服务器           |
| 多设备同步 | 自带，0 元          | 要额外方案   | 自带，历史版本要付费 |
| 打开方式   | 浏览器 / PWA        | 桌面客户端   | 浏览器               |
| AI 接进来  | 原生 MCP            | 靠插件       | 官方 AI              |
| 折腾成本   | 部署 10 分钟        | 插件配一天   | 几乎为零             |

一句话概括：**想要"数据在我手里 + 手机电脑无缝 + 不花钱"，选它；想要插件生态和完全离线，还是 Obsidian。**

我自己的判断是，它更接近"一个能自己掌控的 Notion"，而不是"Obsidian 的替代品"。
