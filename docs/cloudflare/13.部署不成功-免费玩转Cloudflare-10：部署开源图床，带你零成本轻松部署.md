## 特性

别一听“开源”就觉得是简陋的半成品，

星哥给大家挑几个最核心的特性说说：

*   **极致白嫖，速度起飞**：依然基于 Cloudflare Pages 部署，白嫖全球 CDN 加速，零成本还能享受飞一般的访问速度。
*   **安全感拉满**：不仅支持 AES + RSA 加密认证，还加上了 TOTP 二次验证（支持 Google Authenticator），你的图床别人想黑都黑不进。
*   **功能多到眼花**：支持多文件批量拖拽上传、图片在线编辑（压缩/改尺寸/转格式）、多格式链接导出（Markdown/HTML/JSON等），甚至还有**随机图片 API**！
*   **架构大升级**：这点必须夸！2.0 采用了 `Functions Advanced Mode + Wrangler Pages Dev` 模式。**以前还要单开一个数据处理端，现在只需要 Cloudflare Pages 一个服务就能搞定**，部署难度直线下降！

## 前置要求

- Cloudflare 账号
- GitHub 账号及 [Personal Access Token](https://github.com/settings/tokens)

> 请务必勾选 **repo** 权限，否则无法访问仓库图片

- 一个 GitHub 仓库（用于存储图片）

## 保姆级部署教程

废话不多说，咱们直接上干货。跟着星哥的步骤，一步步来。

### 第一步：获取源码

首先，咱们去 GitHub 把项目源码“搬”回自己的仓库。

打开项目地址：[Cf-Github-ImgBed](https://github.com/Stoeaves/Cf-Github-ImgBed)

点击页面右上角的 **Fork**。

> 💡 **星哥温馨提示**：Fork 的同时别忘了顺手点个 **Star** 支持一下作者，这也是咱们白嫖党的基本修养嘛！

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1784794791194.png?tx)

### 第二步：在 Cloudflare 部署 Pages

1. 登录你的 Cloudflare 账号，进入左侧菜单的 **Workers & Pages**。
2. 点击 **创建应用程序**，选择 **Pages**，然后点击 **连接到 Git**（导入现有 Git 仓库）。
3. 选择你刚才 Fork 的仓库。

![img](H:\typora_images\QQ_1784794909761.png)

4. **关键配置来了**，按照星哥给的参数填：
   * **框架预设**：选择 `Vue`
   * **构建命令**：`npm run build`
   * **输出目录**：`dist`

![img](H:\typora_images\QQ_1784795056097.png)



填好后，点击保存并部署，泡杯茶等它跑完就行。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1784795105463.png?tx)

部署成功访问测试

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1784795501225.png?tx)



### 第三步：创建并绑定 KV 数据库

图床的设置和公开图片列表需要地方存，这时候就要请出 Workers KV 了。

在 Cloudflare 左侧菜单找到 **Workers KV**，点击 **创建**。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1784795158746.png?tx)

随便起个名字（比如 `imgbed-kv`），创建完成后，回到刚才部署好的 **Pages** 项目。

![img](H:\typora_images\QQ_1784795174162.png)

进入项目的 **设置** -> **绑定** -> **添加绑定**。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1784795837592.png?tx)

变量名填 `IMG_KV`（或者你喜欢的名字，记住就行），类型选 **KV 命名空间**，选择刚才创建的 KV。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1784795877291.png?tx)



### 第四步：配置环境变量（重点易错区）

这一步是核心，大家仔细看。进入 Pages 的 **设置** -> **变量和密钥**，添加以下 4 个环境变量：

| 变量名            | 必填 | 说明                                                |
| :---------------- | :--: | :-------------------------------------------------- |
| `GITHUB_TOKEN`    |  ✅   | 你的 GitHub Personal Access Token（需有 repo 权限） |
| `ADMIN_PASSWORD`  |  ✅   | 你自己设定的管理员登录密码                          |
| `RSA_PUBLIC_KEY`  |  ✅   | RSA 公钥（base64格式）                              |
| `RSA_PRIVATE_KEY` |  ✅   | RSA 私钥（base64格式）                              |



获取GitHub Personal Access Token：

https://github.com/settings/personal-access-tokens





### 密钥怎么生成？

别慌，2.0版本贴心地内置了生成工具。

在浏览器访问你刚部署的域名，并在地址栏后面加上 `/generate-keys.html`。

例如：`https://your-site.pages.dev/generate-keys.html`

打开页面后，点击按钮生成，把输出的公钥和私钥复制，填到刚才的环境变量里。



> 🚨 **星哥血泪避坑指南**：
> 填写完环境变量后，**千万千万千万要重新部署一遍！！！** 
> 去 Pages 的 **部署** 页面，手动触发一次重新部署，不然环境变量不生效，别怪星哥没提醒你啊！

`[图片：手动重新部署按钮截图]`





### 第五步：登录与初始化

重新部署生效后，访问你的域名，输入刚才设置的 `ADMIN_PASSWORD` 登录后台。

进入 **设置** -> **添加仓库**，填写你的 GitHub 仓库信息。

> ⚠️ **注意一个反直觉的坑**：
> 请保证你绑定的 GitHub 仓库中**至少有一个文件**（随便传个 txt 进去都行）。如果是完全空的仓库，会导致后续无法上传图片！

`[图片：后台添加仓库及上传界面截图]`

搞定！现在你可以愉快地拖拽、批量上传图片，享受丝滑的图床体验了。
