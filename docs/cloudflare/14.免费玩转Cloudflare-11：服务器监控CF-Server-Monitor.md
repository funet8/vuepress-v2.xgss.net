## 它是怎么跑起来的

架构不复杂，但挺巧妙的。

后端逻辑跑在Cloudflare Workers上，数据存D1，实时状态用Durable Objects管理。每台被监控的服务器上装个探针，定时把CPU、内存、磁盘、网络流量这些数据上报上去。

关键点来了：**全程跑在Cloudflare的免费额度里。**

Workers每天10万次请求，D1每天500万行读取，Durable Objects的免费额度对个人用户也绰绰有余。监控个十几台服务器，一分钱不花。

不是试用，是正儿八经的免费。

## 探针安装，一行命令的事

探针的兼容性是我比较惊喜的地方。

Linux、Alpine Linux、Windows都能跑，这不算稀奇。

稀奇的是它支持**OpenWrt**。

玩软路由的朋友都知道，大部分监控方案的探针在路由器上根本装不了。这个能装，而且是唯一一个我见过的免费方案。

安装方式也简单，一行curl命令，下载探针脚本，注册成系统服务，完事。

Ubuntu上我试了，不到两分钟搞定。

## 功能特点

- 📊 **实时监控**：CPU、GPU、内存、磁盘、网络、进程数、连接数、负载均衡
- 📈 **历史图表**：支持 7 天历史数据查看
- 🌍 **全球地图**：可视化展示服务器分布
- 🔔 **离线告警**：支持 Telegram、企业微信 / 飞书 / Bark / 钉钉 / OneBot 通知
- 📱 **响应式**：支持桌面端和移动端
- 🔄 **自动部署**：GitHub Actions 一键部署
- 🗺️ **网络质量追踪**：国内电信/联通/移动/字节延迟与丢包率监测
- 🔒 **服务器隐藏**：可设置特定服务器对非登录用户隐藏
- ↕️ **拖拽排序**：后台拖拽调整服务器显示顺序
- 🌐 **双语支持**：支持中文和英文界面自由切换
- 🧩 **多站点支持**：可配置多个 API 站点聚合展示，详情页与后台按站点独立访问
- 🧪 **本地测试**：支持本地模拟数据生成，方便开发和测试
- 🔐 **Turnstile 验证**：集成 Cloudflare Turnstile 人机验证，增强 API 安全性
- 🔑 **JWT 认证**：登录系统采用 JWT token 认证，支持自定义密钥
- 🛡️ **CSP 安全策略**：默认限制第三方静态资源加载，可在后台按需添加可信白名单
- 🎨 **主题商店**：后台可选择第三方主题和版本，Workers 仅反代主题 `index.html` 与 `assets/`
- 📉 **额度查询**：后台可查询 Cloudflare D1 与 Workers 当日/昨天用量
- ⚡ **实时推送**：基于 Durable Objects + WebSocket，探针上报后页面立即刷新，无轮询延迟

# CloudFlare部署

## 部署服务端

## 前置要求

需要注册以下账户

Cloudflare 账户

GitHub 账户

方式一：Cloudflare Workers 连接GitHub仓库（推荐使用，方便同步）图文教程 -> https://huilang.me/cf-server-monitor-setup/

## 第一步：Fork 项目

打开：https://github.com/huilang-me/CF-Server-Monitor

点击右上角 **Fork** 按钮，将项目 Fork 到你的 GitHub 账户。

## 第二步：新建 Cloudflare Workers

登录 [Cloudflare 控制台](https://dash.cloudflare.com/)

进入 **[Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages)**

点击 **Create application**

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786523325741.png?tx)

选择 Continue with GitHub（第一次使用需要连接 GitHub 账户），选择本项目

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786523354484.png?tx)

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786523495321.png?tx)

### 填写信息

1. Project Name填写：`cf-server-monitor`
2. Build command 填写：`npm run build:frontend`
3. Deploy command 保留默认值：`npx wrangler deploy`
4. 点击 **Deploy**，成功会在底部显示`✨ Success! Build completed.`

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786523543937.png?tx)

把非生产分支勾选到

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786526703262.png?tx)



## 第三步：配置环境变量

### 添加秘钥API_SECRET

1. 在当前Workers & Pages页面，点击 **Settings**
2. 在Variables and secrets找到API_SECRET，点右侧编辑，填写密码（建议使用随机数,不要包含特殊字符比如%），点Deploy保存部署，等待30秒左右部署完成

## 第四步：域名和后台配置

### 查看域名和绑定域名

点击顶部的**域**，可用查看项目域名，比如我这个的cf-server-monitor.song-ade.workers.dev

这里在右下角可用绑定你自己的域名（默认的域名部分地区可能不能访问。有自己域名的，建议绑定一个）

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786529353475.png?tx)

访问这个域名，会看到成功部署了，至此Cloudflare Workers部署完成。

## 第五步：后台管理与设置

访问后台地址/admin, 默认用户名admin，默认密码是刚才API_SECRET的值。

![img](https://imgoss.xgss.net/picgo-tx2026/2026-06-19-243.png?tx)

第一次设置请修改用户名和密码，强烈建议设置JWT密钥。其他选项可用根据需求进行设置，Turnstile以及Cloudflare设置等高级用法在后面补充。

### 添加服务器

在服务器tab添加服务器名称和分类名称，点添加服务器

![img](https://imgoss.xgss.net/picgo-tx2026/2026-06-19-398.png?tx)

添加完，可用点右侧的编辑，根据实际进行修改

![img](https://imgoss.xgss.net/picgo-tx2026/2026-06-19-252.png?tx)

![img](https://imgoss.xgss.net/picgo-tx2026/2026-06-19-611.png?tx)

保存后，点刚才编辑按钮左侧的复制按钮，会出来一个弹窗

![img](https://imgoss.xgss.net/picgo-tx2026/2026-06-19-663.png?tx)

这里根据需要选择系统，如果需要校正月流量，在这里填写，然后点复制命令。

```
curl -sL https://你的域名/install.sh | bash -s install xxx
```

将你复制出来的命令粘贴在你的服务器上运行即可（需要root权限）。
