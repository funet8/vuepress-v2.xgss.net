## 重要的和不重要的，挤在同一个渠道里

这才是问题的根。

不是通知太多，是你没办法区分哪个该看、哪个该扔。

微信群里，领导@你和同事发"哈哈哈"是同一个弹窗。

邮箱里，部署失败告警和营销邮件躺在同一个收件箱。

手机推送栏，AI 任务完成的通知和某宝优惠券并排显示。

你的大脑只能做一个选择：要么全看，累死；要么全不看，漏事。

我选了第三条路——**单独开一个通道，只放真正重要的。**



## 我的方案：ntfy，一个极简的推送服务

ntfy 是个开源的消息推送工具，轻量到令人发指。

一个 Docker 容器就能跑起来，没有数据库，没有复杂的后台，甚至连注册都不需要。

它的逻辑特别简单：

> 你往一个 topic 发消息，订阅了这个 topic 的设备就会收到推送。

就这么回事。

没有算法推荐，没有"猜你喜欢"，没有已读未读。

**你发什么，我收什么。仅此而已。**



## 我现在怎么用的

给自己定了几条死规矩：

**只推这几种情况：**

- AI 任务跑完了 → 推
- 任务挂了、报错了 → 推
- 每天精选的技术资讯汇总好了 → 推
- GitHub 上发现值得关注的新项目 → 推

**其他一律不推：**

- 任务还在跑？不推。
- 常规查询有结果了？不推。
- 没什么新内容？不推。

效果呢？

**一天大概响 3 次。每次响，我都确切知道：有事，得看一眼。**

不响的时候，我就踏踏实实写代码、开会、摸鱼，心里没有任何负担。



## 使用ntfy

网址：`ntfy.sh`

注册一个账号，再添加一个订阅主题即可，这个是通知到你的浏览器的。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786678461507.png?tx)

```
curl -d "Hi" https://ntfy.sh/你建的订阅主题
```

### 2.手机app

官方支持安卓和IOS

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1786679161498.png?tx)

手机去应用商店搜 "ntfy" 装个 App，然后终端里一行命令就能发：

```bash
curl -d "任务跑完了" ntfy.sh/你的随机topic名
```

个人用，绰绰有余。

### 3.自托管，完全私有

一台服务器，一条 Docker 命令：

docker 部署服务端

```bash
docker run -d \
  --name ntfy \
  -p 85:80 \
  -v /var/cache/ntfy:/etc/ntfy \
  binwiederhier/ntfy serve
```

搞定。

想加认证的话，改一下配置文件，把 `auth-default-access` 设成 `deny-all`，再创建个用户就行。

自托管的好处：没有频率限制，topic 别人猜不到，数据完全在自己手里。

docker-compose 部署服务端

```
services:
  ntfy:
    image: binwiederhier/ntfy
    container_name: ntfy
    command:
      - serve
    environment:
      - TZ=UTC    # optional: set desired timezone
    user: UID:GID # optional: replace with your own user/group or uid/gid
    volumes:
      - /var/cache/ntfy:/var/cache/ntfy
      - /etc/ntfy:/etc/ntfy
    ports:
      - 80:80
    healthcheck: # optional: remember to adapt the host:port to your environment
        test: ["CMD-SHELL", "wget -q --tries=1 http://localhost:80/v1/health -O - | grep -Eo '\"healthy\"\\s*:\\s*true' || exit 1"]
        interval: 60s
        timeout: 10s
        retries: 3
        start_period: 40s
    restart: unless-stopped
    init: true # needed, if healthcheck is used. Prevents zombie processes
```

## 脚本推送也很简单

Python 几行代码的事：

```python
import requests

def push(title, body, topic="你的topic", server="https://ntfy.sh"):
    requests.post(
        f"{server}/{topic}",
        json={"message": body, "title": title, "markdown": True}
    )

# 用法
push("✅ 任务完成", "今日 GitHub Trending 已汇总，共 5 条")
```

配合 cron 定时任务，或者塞进你现有的自动化脚本里，完事。

最简组合就是 **ntfy + cron**，连 n8n 都不需要。



## 踩了几个坑

### **坑一：中文标题乱码**

用 Python 自带的 `urllib` 发中文，通知栏显示一坨火星文。

原因：`urllib` 对 header 的 UTF-8 编码处理有 bug。

解法：换 `requests` 库，或者直接 subprocess 调 curl。别跟 urllib 较劲。



### **坑二：topic 被人蹭了**

最开始我用 `test` 当 topic 名，结果发现消息发出去没反应——后来才知道，公共服务的 topic 是全局共享的，别人也在用这个名字。

解法：起个足够随机的名字。自托管的话直接开认证，一劳永逸。



### **坑三：批量推送被限流**

写了个脚本一口气推 300 条，推到后面就发不出去了。

官方限制每小时 250 条。

解法：脚本里加个 `time.sleep(1)`，或者干脆自托管，没这破限制。
