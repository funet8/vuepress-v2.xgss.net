# 在 NAS 上跑个微信机器人：WeChatPadPro 部署实录，附扫码登录全过程

**导读：** 一个 2.6k Star 的开源项目，能把微信变成一个 HTTP 接口——程序可以替你收发消息。我在飞牛 NAS 上用 Docker 跑了一遍，从建目录到扫码登录大概半小时。这篇把完整过程和踩到的坑原原本本写下来，包括**必须先看的那几条风险**。



## 先说清楚，这东西到底是个啥

WeChatPadPro，GitHub 上 2.6k Star、543 个 Fork，Go 写的，2025 年 3 月建仓，最近一次代码提交是今年 8 月，一直没停。

它的官方描述是"基于 WeChat Pad 协议的高级微信管理工具"。翻译成人话：

**它把微信包装成了一个 HTTP API 服务。**

跑起来之后，你手上会多一个 `http://内网IP:1238` 的管理页面，页面上排着一长串接口——发消息、收消息、拉群成员、消息防撤回……你想要的操作，基本都能通过一次 HTTP 请求完成。

所以它不是"更好用的微信客户端"。**它是要让程序去用微信。**

谁需要这个？我理解下来是三拨人：

- **个人玩家**：给自己的号接个 AI 助手，或者做消息归档、防撤回
- **开发者**：拿微信当消息通道，做通知、做自动化
- **做私域运营的**：客服号、批量操作（这部分我不评价，往下会专门说风险）

有个数据挺能说明问题。最新版本 v2.01（2025 年 8 月发布）的 GitHub 下载量：Windows 版 3182 次、Linux amd64 版 2438 次、macOS ARM 版 1088 次，各平台加起来超过 9000 次。

**这不是个玩具，真有人在用。**



## ⚠动手之前，丑话说在前面

我知道看到"微信 + 协议"这几个字，老玩家心里都清楚是什么路数。所以这几条我放最前面，一条都别跳过。

**第一，这是第三方协议，不是官方接口。** 它模拟的是 iPad 端微信的登录链路。这件事明确违反微信的用户协议——不是"可能违反"，是明确违反。

**第二，封号风险是真的。** 我在社区里看到过一份封禁梯度：操作过于频繁封 1 天、功能封锁 7 天、限制登录 30 天、永久封禁。前两级还有申诉空间，到了永久那一档基本就回不来了。

**第三，登录地是最容易出事的点。** 服务器挂在深圳、人常年在北京，这种"异地长期在线"的账号最容易被风控盯上。放在家里 NAS 上，风险比放云服务器低不少。

**第四，别拿主号玩。** 这句是重点里的重点。想试，去找一个不重要的小号。

**第五，关于授权。** 社区文档里提到这类项目可能需要额外的 token 或授权才能长期稳定运行，官方仓库里没有明确写，具体政策得去它自己的 TG 群看。我不替它背书，你自己判断。

看完这些你还想折腾，那咱们就当技术练习，往下走。

## 开始前，先备齐这几样

- 一台跑 **飞牛 NAS** 的设备（其实任何能跑 Docker Compose 的 Linux 机器都行）
- 一个可以拿来试的微信号（能扫码登录就够）
- 十分钟耐心，拉镜像的时间看网速

飞牛的 Docker 是全图形化界面，我下面就按界面操作走。习惯命令行的朋友，直接 `docker compose up -d` 也是一样的。

---

## 第一步：先建一个文件夹

去文件管理器里，挑个位置建一个目录，比如：

```text
/docker/wechatpadpro
```

这个目录要干两件事：**放配置文件**，同时**作为 Compose 项目的工作目录**。MySQL 和 Redis 的数据后面也会落到这里，所以别建在系统盘上。

---

## 第二步：把 .env 拿下来，改掉 ADMIN_KEY

从仓库的 `deploy` 目录下载 `.env`：

```text
https://github.com/WeChatPadPro/WeChatPadPro/blob/main/deploy/.env
```

下载完丢进第一步那个目录。

打开看一眼，里面绝大多数参数不用动，**但有一个必须改：`ADMIN_KEY`**。

它的默认值是 `changeme`。这个 Key 就是整个管理后台的钥匙——后面生成授权码、登录，全靠它。你不改，等于把后台敞着门放在局域网里等人进。

改成一串自己的随机字符串，**记好**，后面要用三次。

---

## 第三步：Compose 起容器

打开飞牛桌面上的 Docker，左侧栏点 **Compose → 新增项目**：

1. 项目名称随便起，比如 `wechatpadpro`
2. **设置路径**选第一步建的那个文件夹（这步选错，`.env` 就读不到）
3. 创建 `docker-compose.yml`，把下面的内容原样粘进去
4. 点完成，等它把镜像拉完

```yaml
version: '3.8'

services:
  wechatpadpro:
    image: wechatpadpro/wechatpadpro:${WECHAT_TAG:-latest}
    container_name: wechatpadpro
    restart: always
    ports:
      - "${WECHAT_PORT:-8080}:8080"
      - "${PORT:-1238}:1238"
    env_file:
      - .env
    environment:
      - DB_HOST=mysql
      - REDIS_HOST=redis
      - TZ=${TZ}
      - GH_WXID=${GH_WXID}
      - ADMIN_KEY=${ADMIN_KEY}
      - WORKER_POOL_SIZE=${WORKER_POOL_SIZE}
      - MAX_WORKER_TASK_LEN=${MAX_WORKER_TASK_LEN}
      - WEB_DOMAIN=${WEB_DOMAIN}
      - WEB_TASK_NAME=${WEB_TASK_NAME}
      - WEB_TASK_APP_NUMBER=${WEB_TASK_APP_NUMBER}
      - NEWS_SYN_WXID=${NEWS_SYN_WXID}
      - DT=${DT}
      - TOPIC=${TOPIC}
      - ROCKET_MQ_ENABLED=${ROCKET_MQ_ENABLED}
      - ROCKET_MQ_HOST=${ROCKET_MQ_HOST}
      - ROCKET_ACCESS_KEY=${ROCKET_ACCESS_KEY}
      - ROCKET_SECRET_KEY=${ROCKET_SECRET_KEY}
      - RABBIT_MQ_ENABLED=${RABBIT_MQ_ENABLED}
      - RABBIT_MQ_URL=${RABBIT_MQ_URL}
      - KAFKA_ENABLED=${KAFKA_ENABLED}
      - KAFKA_URL=${KAFKA_URL}
      - KAFKA_USERNAME=${KAFKA_USERNAME}
      - KAFKA_PASSWORD=${KAFKA_PASSWORD}
      - TASK_RETRY_COUNT=${TASK_RETRY_COUNT}
      - TASK_RETRY_INTERVAL=${TASK_RETRY_INTERVAL}
      - HEARTBEAT_INTERVAL=${HEARTBEAT_INTERVAL}
      - AUTO_AUTH_INTERVAL=${AUTO_AUTH_INTERVAL}
      - AUTO_SYNC_INTERVAL_MINUTES=${AUTO_SYNC_INTERVAL_MINUTES}
      - TASK_EXEC_WAIT_TIMES=${TASK_EXEC_WAIT_TIMES}
      - QUEUE_EXPIRE_TIME=${QUEUE_EXPIRE_TIME}
      - WS_HANDSHAKE_TIMEOUT=${WS_HANDSHAKE_TIMEOUT}
      - WS_READ_BUFFER_SIZE=${WS_READ_BUFFER_SIZE}
      - WS_WRITE_BUFFER_SIZE=${WS_WRITE_BUFFER_SIZE}
      - WS_READ_DEADLINE=${WS_READ_DEADLINE}
      - WS_WRITE_DEADLINE=${WS_WRITE_DEADLINE}
      - WS_PING_INTERVAL=${WS_PING_INTERVAL}
      - WS_CONNECTION_CHECK_INTERVAL=${WS_CONNECTION_CHECK_INTERVAL}
      - WS_MAX_MESSAGE_SIZE=${WS_MAX_MESSAGE_SIZE}
      - CLUSTER_NAME=${CLUSTER_NAME}
      - ZK_ADDR=${ZK_ADDR}
      - ETCD_ADDR=${ETCD_ADDR}
      - DISABLED_CMD_LIST=${DISABLED_CMD_LIST}
      - MYSQL_CONNECT_STR=${MYSQL_CONNECT_STR}
    volumes:
      - ./.env:/app/.env
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - wechatpadpro-network

  mysql:
    image: mysql:8.0
    container_name: mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-root123456}
      MYSQL_DATABASE: ${MYSQL_DATABASE:-weixin}
      MYSQL_USER: ${MYSQL_USER:-weixin}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD:-weixin123}
    ports:
      - "${MYSQL_PORT:-3306}:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p${MYSQL_ROOT_PASSWORD:-root123456}"]
      interval: 5s
      timeout: 5s
      retries: 20
    networks:
      - wechatpadpro-network

  redis:
    image: redis:6
    container_name: redis
    restart: always
    command: redis-server --appendonly yes
    ports:
      - "${REDIS_PORT:-6379}:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 5s
      retries: 20
    networks:
      - wechatpadpro-network

networks:
  wechatpadpro-network:
    driver: bridge

volumes:
  mysql_data:
  redis_data:
```

这段是**官方仓库里的原版 compose**，一个字没改。如果复制过程中担心格式出问题，最稳的办法是直接从仓库的 `deploy` 目录把 `docker-compose.yml` 下载下来，放进同一个文件夹——效果一样。

---

## 第四步：打开管理页面

浏览器访问：

```text
http://你NAS的内网IP:1238
```

注意端口是 **1238**，不是 8080。8080 是另一个服务端口，管理后台在 1238。

页面打开后是一个接口调试界面，左边可以按名字搜接口。

---

## 第五步：生成授权码

1. 页面顶部有个输入框，**先填 ADMIN_KEY**——就是第二步改的那串
2. 往下找到 `/admin/GenAuthKey1`（生成授权码·新设备），点开
3. 点 **Execute（执行）**，会返回一串密钥
4. **把这串密钥完整复制下来**

---

## 第六步：扫码登录

这是全程最关键的一步，顺序别搞错：

1. 回到页面顶部，找到 **TOKEN_KEY** 那个输入框，把刚才复制的密钥粘进去
2. ⚠️ **粘完不要刷新页面**——一刷新就得从头再来
3. 往下找到 `/login/GetLoginQrCodeNew`（获取登录二维码），点开，Execute
4. 返回值里会带一个链接，复制到浏览器打开，就是一个二维码
5. 用你要登录的那个微信扫码

扫完页面顶部会显示 **iPad 在线**。到这儿，登录就成了。

后面就可以对接机器人框架了，社区里比较常见的玩法是接 LangBot 或者 OpenClaw 的微信插件，把它当成一个消息通道来用。

## 我踩到的 5 个坑

**坑 1：刷新页面等于前功尽弃。**

TOKEN_KEY 是存在页面内存里的，一刷新就没了，得重新生成授权码走一遍。操作的时候忍着别按 F5。

**坑 2：首次登录 24 小时内大概率掉线一次。**

社区里普遍反馈的现象，不是你配错了。掉了就用同一个授权码重新扫码，之后就稳了。

**坑 3：别频繁换网络和登录地。**

一会儿家里 NAS、一会儿云服务器、一会儿又挂上代理——风控最喜欢抓这种账号。**固定设备、固定出口 IP**，是新号活下来的基本操作。

**坑 4：端口别乱开。**

默认 compose 里，MySQL 的 3306 和 Redis 的 6379 是映射到宿主机的。但这俩**只需要容器内部访问**，完全可以把这两段 `ports` 删掉。

如果你打算把它放到有公网的服务器上——那就更别开。要远程访问，老老实实走 VPN 或者内网穿透再加一层鉴权。

**坑 5：外网访问必须套 TLS。**

局域网自用无所谓。但只要你想从外网打开这个后台，请务必在前面架一层反向代理加上 HTTPS，别裸奔。

## 说点我的真实看法

技术上，这东西做得确实漂亮。Go 单文件二进制，Windows、macOS、Linux 各种架构都发了包，Docker 一把梭就能起，接口文档还直接嵌在页面里让你点着调试。**2.6k Star 不是白来的。**

但我也得说句实话——**它解决的，是一个本来不该用这种方式解决的需求。**

微信对这个生态的态度一直很明确。好消息是，今年 3 月微信通过 OpenClaw 正式开放了个人号的 Bot API（iLink 协议，接入域名在 `ilinkai.weixin.qq.com`），官方、合法、不用扫码、不怕封号，支持文本图片语音文件视频。

坏消息是，它限制也很硬：

- **只能被动回复**，用户先发消息你才能回，不能主动发起对话
- **进不了群聊**
- **用户超过 24 小时没说话，token 就过期了**，回不了

所以你看，官方的路合规但"手脚被绑住"，第三方协议能做的多得多——代价就是把账号押上去。

这就是为什么 WeChatPadPro 这类项目一直有人折腾：**它开出来的口子，比官方大太多了。**

我的建议很朴素：

- **想学习、想搞明白协议怎么走的**——拿小号，放内网，别高频操作，没问题
- **生产环境、企业客服号、你的主号**——别碰，真的别碰

技术归技术，账号归账号。这两样东西，最好不要放在一个篮子里赌。

## 想放云上跑？先算一下配置

如果你没有 NAS，或者不想让家里的设备 7×24 转着，想把这套东西丢到云服务器上。

提醒一句：它自带 **MySQL + Redis 两个依赖**，内存开销不小。1G 的轻量机跑起来会非常紧张，建议 **2G 起步**，不然容器很容易被 OOM 干掉。

要买的话，可以顺手比一下官方活动价。阿里云走 `y.xgss.net/a`，腾讯云走 `y.xgss.net/tx`，都是官方下单渠道，不会额外加价。

---

## 星哥的云上小店

如果你刚好要买云服务器、对象存储或其他云产品，可以走星哥的官方推广渠道：

- 阿里云：`y.xgss.net/a`
- 腾讯云：`y.xgss.net/tx`

不额外收费，复制地址到浏览器打开即可，也算支持我继续折腾和实测这些工具。
