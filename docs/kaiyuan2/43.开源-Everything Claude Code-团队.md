大家好，我是星哥。短短几个月，狂揽十几万 Star（直逼 20 万大关），在开发者圈子里可以说是“杀疯了”。

它叫 **Everything Claude Code（简称 ECC）**。

如果你最近在用 Claude Code、Cursor 或者 Codex 写代码，星哥强烈建议你花 3 分钟看完这篇文章，它可能会彻底颠覆你的 AI 编程体验。



## 一、黑客松冠军的“秘密武器”

这个项目的诞生，其实源于一场“开挂”般的黑客松比赛。

去年 9 月，Anthropic 和 Forum Ventures 搞了个硬核比赛，主题很吓人：**「用 AI Agent 从零到一构建一家公司」**。

规则极其变态：要把平时花几周才能干完的活（找精准客户、做需求规划、画原型、写代码），压缩在**一天内**搞定。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1783935278189.png?tx)

结果，旧金山开发者 Affaan Mustafa 和他的队友，不仅按时交卷，还拿了冠军。

他们做出来的 AI 客户调研平台 `zenith.chat`，几乎全是靠 Claude Code 自动生成的，作者自嘲“基本没怎么亲手敲过代码”。

凭什么这么猛？

就凭 Affaan 私下里偷偷打磨了**十个多月的一套 Claude Code 终极工作流**。

比赛一结束，他把这套工作流直接开源，这就是今天霸榜的 ECC。

开源介绍

## 二、给 AI 配一个“全自动团队”

经过三个多月的疯狂迭代，现在的 ECC 已经是个庞然大物：**60多个 Agent、260多个 Skill，外加近百个斜杠命令**。

给 Claude Code 装上它，就相当于给它配了一支**分工明确的硅谷 AI 团队**：
- 🧠 **架构师 Agent**：专门做系统设计和架构决策。
- 🛡️ **安全审查 Agent**：揪出代码里的安全漏洞。
- 🧪 **TDD 测试 Agent**：自动写测试用例，保证代码质量。
- 🧹 **重构清理 Agent**：专门清理无效代码和坏味道。



**星哥觉得最实用的有两个黑科技：**

**第一是“跨会话记忆”。**

用过 AI 编程的兄弟都知道，换个会话 AI 就“失忆”了。ECC 的钩子（Hooks）能在不同会话间自动存取上下文，让 AI 真正拥有“长期记忆”，越用越懂你的项目。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1783934614134.png?tx)

**第二是“按需加载”，绝不撑爆上下文。**

一开始看到 200 多个技能，星哥第一反应是：这不得把上下文窗口撑爆？

后来发现人家聪明得很。它是**按需唤醒**的：你写 TypeScript，它就只加载 TS 审查 Agent；你搞 Python 测试，TDD Agent 才会启动。这就保证了庞大的技能库不会拖慢 AI 的脑子。



## 三、毫秒级防泄露，红蓝对抗保平安

用 AI 写代码，大家最怕什么？
怕 AI 一不留神，把你的**私钥、API Token 直接提交到公共仓库**，底裤都赔掉。

ECC 内置了一个叫 **AgentShield** 的安全审计工具，能毫秒级扫描代码，死死拦住凭证泄露。

如果你开启 `--opus` 模式，好戏就开场了：它会直接召唤**三个 Opus 智能体分身**搞“红蓝对抗”：
- 🔴 **红队 Agent**：千方百计找漏洞、想攻击链。
- 🔵 **蓝队 Agent**：负责评估防护、修复漏洞。
- ⚖️ **审计师 Agent**：综合两边意见，出具优先级风险报告。

这哪是写代码，这简直是在公司里养了个安全攻防实验室！



## 四、怎么装ECC？

### 安装ECC

ECC 不仅支持 Claude Code，Codex、Cursor 等主流工具也能用。

安装很简单，官方推荐**插件安装法**，两行命令搞定：

```bash
# 添加市场
/plugin marketplace add https://github.com/affaan-m/ECC

# 安装插件
/plugin install ecc@ecc
```
![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1783934267099.png?tx)

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1783934520249.png?tx)

*(注：因为插件系统限制，`rules` 规则文件需要你手动去仓库克隆，并把对应的语言目录复制到 `~/.claude/rules/` 下。)*

⚠️ **但是！这里有个巨坑，大家千万别踩：**

**绝对不要一次性启用所有的 MCP（模型上下文协议）服务！**
有些兄弟有“火力不足恐惧症”，装完把所有工具全打开。结果呢？原本 200K 的上下文窗口，**瞬间被挤占缩水到 70K**，AI 直接变傻。

**星哥的建议配置：**

- 全局配置 20-30 个 MCP 即可。
- 单个项目启用**不要超过 10 个**。
- 活跃工具控制在 80 个以内。用不到的，果断在配置里禁用掉。

### 使用ECC

```
# 尝试一个命令（插件安装使用命名空间形式）
/ecc:plan "添加用户认证"

# 手动安装（选项2）使用简短形式：
# /plan "添加用户认证"

# 查看可用命令
/plugin list ecc@ecc
```



**完成！** 你现在可以使用 67 个代理、278 个技能和 94 个命令。

## 星哥锐评：AI 时代的“调教”才是核心竞争力



说实话，ECC 在 GitHub 上也有不少争议。吐槽最多的就是：**功能太多太杂，普通人根本用不到 10%**。

作者 Affaan 自己也坦言，这套配置是高度定制化的，是根据他个人的工作流打磨出来的。

所以，星哥给大家的建议是：**不要做“收藏党”，要学会“断舍离”。**

挑适合自己的，删掉用不上的，加上你自己业务特有的规则，**构建一套专属你自己的工作流**，这才是正确的打开方式。

**写在最后：**
从早期的“代码自动补全”，到现在的“多 Agent 协同系统”，AI 编程工具的进化速度令人发指。

现在，**技能、规则、记忆、安全这些“配置”，已经变得和底层大模型一样重要了。**

ECC 能在三个月狂揽近 20 万 Star，足以证明一个趋势：
**未来，当大模型的能力强到一定程度，真正拉开程序员差距的，不再是谁的代码敲得快，而是谁更懂得如何去“编排”和“调教” AI。**
