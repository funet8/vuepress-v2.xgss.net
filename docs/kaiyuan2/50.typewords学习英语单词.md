# 打字也能背单词？这个 1 万 Star 的开源神器，把我十年的英语学习方式给改了

**导读：** 背单词这事儿，谁背谁痛苦。最近我发现一个开源项目 TypeWords，把「打字练习」和「背单词」缝在了一起——一边敲键盘，一边就把单词记住了。GitHub 上已经 1 万多 Star，在线就能用，本地也能自己部署。

今天聊聊它到底值不值得试。

## 开源免费的 TypeWords 到底是个啥

一句话说清：**它是一个用「打字」来背单词和背课文的开源工具。**

你不用抄、不用念，就是对着屏幕**敲键盘**。敲对了往下走，敲错了卡住重来。整个过程像是在做打字练习，但脑子一直在跟着单词转。

项目的理念写得挺有意思：

> 学习英语，一次敲击，一点进步；记忆不再盲目，学习更高效。

![img](https://imgoss.xgss.net/picgo-tx2026/QQ_1789876374458.png?tx)

我试了几分钟就理解了为什么这个思路有效。打字这东西有个特点——**它骗不了人**。

眼睛看一遍觉得自己记住了，手一敲就露馅。所以它天然带着"强制回忆"的效果，这恰恰是背单词最缺的那一环。

更关键的是，敲键盘有节奏感、有反馈、有速度可刷。

同样是背 20 个单词，抄写像坐牢，打字像玩游戏。

**这东西在 GitHub 上已经 1 万多 Star 了**，项目从 2023 年就开始更新，最近一次提交就在今年 9 月，不是那种发完就跑路的。

- 开源地址：`https://github.com/zyronon/TypeWords`
- 演示网址：`https://typewords.cc`



## 三个真香功能

### 一、四种模式，难度是一级一级加上去的

这是我最喜欢的设计。它不是上来就让你默写，而是分了四档：

- **跟打模式**：单词和释义词都在屏幕上，照着敲。相当于熟悉阶段
- **辨认模式**：只给中文释义，让你把英文敲出来。开始上强度了
- **复习模式**：把之前学过的拿出来过一遍
- **默写模式**：不给提示，全凭记忆敲——这个是动真格的

四档走下来，其实就是一个**从"认识"到"记住"的完整路径**。你可以一直停在跟打模式自欺欺人，也可以一路推到默写模式看看自己到底记住几个。

### 二、记忆曲线是自动算的，不用自己排复习表

我原来也用过记忆曲线那套方法，但**自己排复习计划这事儿本身就很难坚持**——今天该复习哪一批、明天又该加哪些，排到第三天就乱了。

TypeWords 是系统自动计算最佳复习时间的。你不用管什么艾宾浩斯第几天，它到点就把该复习的推给你。

**这省下的不是时间，是心力。**

### 三、每个单词给的东西，比我预想的多

点开一个单词，给的不只是"词 + 释义"：

音标、美音发音、英音发音、例句、常用短语、近义词、甚至词源。

我特别喜欢**词源**这一块。有些词知道它从哪来的之后，基本就不会忘了，比硬记拼写牢得多。这种细节，能看出来作者是真在学英语的人，不是随便套个模板。

## 文章背诵：这才是它真正的杀手锏

如果说背单词功能是"挺好"，那**文章背诵**这块，是真的戳到我了。

还记得我开头说的那个问题吗——翻译看得懂，原文读不了。**根本原因是我从来没"输出"过英文。**

TypeWords 的文章模式是这么干的：

- **内置了不少经典教材**，不用自己找素材
- **也能自己导入文章**，你把想啃的技术文档贴进去也行
- 支持**一键翻译、译文对照、逐句输入**
- **自动发音**，甚至可以边听边默写

也就是说，你不是读一遍就过，而是要**一句一句把它敲出来**。这个过程非常慢、非常累——但你敲完一篇，那篇东西是真进脑子了。

阅读能力弱的根子，往往不是词汇量，而是**句子结构和语感没建立起来**。一句句敲，恰恰是在最笨也最有效地解决这个问题。

## 怎么用？

好在这个项目**不折腾**，你想怎么用都行。

### 路线一：在线版，最省事

浏览器直接打开 `https://typewords.cc` 

就能用，不用注册、不用装任何东西。**先试试再说**，这是我最推荐的第一步。



### 路线二：本地跑起来，数据放自己机器上

这个项目是 Vue 写的，本地跑需要 Node 环境。我自己用的是 `v22.12.0`，流程就三步：

```bash
npm install     # 装依赖
npm run dev     # 启动，默认 http://localhost:3000
npm run build   # 打包
```

源码从 GitHub 上拉下来，进项目根目录敲这几行就行。

**数据是存在浏览器本地的**——好处是隐私完全在自己手里，坏处是换设备得手动备份。这点后面还会说。



### 路线三：Docker 部署，适合有服务器的兄弟

如果你手头正好有一台云服务器或者 NAS，那就干脆部署成常驻服务，手机浏览器也能随时打开。

先 `npm run build` 打包，然后写个 `Dockerfile`：

```dockerfile
FROM nginx:1.21.5
LABEL maintainer="xj"
WORKDIR /usr/share/nginx/html
COPY ./dist/ ./
RUN chmod -R 755 /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

把打包出的 `dist` 目录放到同级，构建镜像：

```bash
docker build -t xj/typewords:v2.0 .
```

再写个 `docker-compose.yml`：

```yaml
services:
  typewords:
    image: xj/typewords:v2.0
    container_name: typewords
    restart: always
    logging:
      driver: 'json-file'
      options:
        max-size: '5g'
    environment:
      - NGINX_PORT=80
    ports:
      - 8090:80
```

启动：

```bash
docker-compose up -d
```

到这就完事了，浏览器打开服务器的 8090 端口就能用。



## 小缺点

用了几天，我觉得有两个地方得提前跟你交个底：

**第一，数据存在浏览器本地，多端不同步。** 

你在电脑上背的进度，手机上打开是空的。想换设备，得手动导出备份。这个对习惯多设备切换的人来说，确实不太友好。

**第二，内置词典的选择比较有限。** 词库不是那种大而全的，想背什么偏门词表可能得自己导入。

不过说实话，这俩问题**放在"开源免费"这个前提下，我觉得都能接受**。项目还在活跃更新，说不定哪天就补上了。
